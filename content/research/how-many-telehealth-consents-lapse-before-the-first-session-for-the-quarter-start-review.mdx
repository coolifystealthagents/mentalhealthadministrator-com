## Question and scope

This review asks how often a scheduled telehealth session begins without a signed consent that covers the session date and matches the version the client received. The unit is the session, because a signed form that exists somewhere in the chart does not prove that the specific visit was covered. A practice can have a high signing rate and still have lapses when renewals, version changes, and scheduling changes are not aligned. Measuring at the session level makes those lapses visible instead of hiding them in a client-level summary.

The scope should name the date range, the telehealth service lines, and the clinicians included. Decide whether the review covers only the first session or every session in the window. A first-session review measures intake readiness, while an all-session review measures ongoing coverage. The two questions need different populations. State which one the practice is asking before drawing the sample.

Include the platform or modality in the scope. A phone visit may have a different consent requirement from a video visit. If the practice uses more than one platform, note which one was used for each session. A consent stored in one platform may not be visible in another, so the review needs to know where to look before it judges a record missing.

## Population and unit of analysis

The population is every scheduled telehealth session in the window that reached the start time. The unit is one session linked to one consent record and one client. If a client has three sessions covered by one consent, count three units and link them to the same form. That approach shows whether the form actually covered each date, which a client-level count would hide.

Exclude sessions that were cancelled before the start time and sessions that were rescheduled to a date outside the window. Include sessions where the client did not attend, because the consent should have been in place before the attempt. Record the exclusion counts so the denominator can be rebuilt. A session-level denominator is more meaningful than a count of forms.

Stratify by service, clinician, new versus established client, and consent version. New clients may have a different intake path than established clients. A version change may create a cluster of mismatches even when the signing process worked. The review should report those strata with counts so a small group is not overinterpreted. Stratification also helps the practice choose which fix to try first.

## Definitions and measures

Define a valid consent as a signed record that covers the session date, matches the version the client received, and is stored where the practice can retrieve it. Define an expired consent as one that was valid for an earlier date but not the session date. Define a missing consent as one with no retrievable record. A version mismatch is a separate category because the client may have signed a different document.

Treat a verbal consent as its own category if the practice permits one. Verbal consent may be valid under the practice's policy for some services, but it needs a documented date and a note of what was explained. Do not count an undocumented verbal consent as a signed record. The review should report each category separately so the reader can see whether the issue is process, versioning, or retrieval.

The primary measure is the share of scheduled sessions without a valid consent on the session date. A secondary measure is the share of records missing a required field such as the signature date, the version, or the client location. Report the count of sessions that were rescheduled because of a consent problem. That count connects the documentation finding to a scheduling consequence.

## Data sources and collection

Use the scheduling system for the session date and the consent platform for the signed record. Use the client chart to confirm which version was sent and when. If the platform keeps an audit log, export the relevant events rather than relying on the current display. A current screen may show a completed consent without showing when it was completed or which version was used.

Match records by a stable identifier, not by name alone. Names can vary by spelling, and a shared family name can cause a wrong match. Record the matching rule and the number of records that could not be matched. An unmatched record is a finding, not a reason to drop the case. The review should keep unmatched sessions in the denominator unless the record is confirmed to belong to another client.

Store the export with the review and note the time it was taken. Consent platforms change state when a client signs, so a later export may not reproduce the review. Keep the original file and any later correction separate. Use a pseudonymous key in the working file and keep the crosswalk in a restricted location. The review should not copy the content of the consent into an unprotected spreadsheet.

## Evidence standard

A signature counts as evidence when the record shows the signer, the date, the version, and the covered service. An image of a signature without those fields is weaker because it cannot show what the client agreed to. If the practice uses an electronic signature, keep the audit trail that records the signing event. The review should be able to point to the stored evidence for every session it marks valid.

When a session is marked as covered, the reviewer should note whether the consent was checked before the session or only afterward. A consent completed after the session does not prove that the session began with coverage, even if it is now in the chart. The review can report both the current coverage rate and the share that was confirmed before the start time. The difference is often the most useful finding.

State what the review does not measure. It does not measure whether the client understood the consent or whether the clinician explained the risks well. It does not decide whether a particular state permits the session. Those are clinical, legal, and training questions. The review measures documentation coverage at the session level and should not be used as a substitute for a compliance opinion.

## Analysis and reporting

Report the primary rate with the numerator, denominator, and window. Break it down by the categories of missing, expired, version mismatch, and verbal-only. Report the share of sessions where the consent was confirmed before the start time. A practice that fixes records after the fact may look complete in the chart while still having a live coverage problem.

Report the strata with counts and rates, and mark any group with a small denominator. Do not compare a stratum of five sessions with a stratum of two hundred as though the rates were equally stable. The report should say which differences are worth investigating and which are too small to interpret. That honesty makes the next review more useful.

Write a short list of process questions raised by the data. A cluster of expired consents may point to a reminder that fires too late. A cluster of version mismatches may point to a platform update that did not trigger a new signature. A cluster of missing records may point to a storage location the coordinator cannot access. The report should not prescribe a clinical response.

## Limits and sources of error

The largest error is a record that exists but cannot be retrieved. A consent stored in a former platform or an old folder may be valid but invisible to the reviewer. The review should record retrieval failures separately and ask the vendor or administrator for an export before concluding that the consent is missing. A missing retrieval is a different problem from a missing signature.

A second error is a date boundary. A consent that expires at midnight may be treated differently depending on the practice's rule and the session time. Record the rule and apply it consistently. If the practice changes the rule during the window, label the change and keep the earlier classification. A boundary dispute can create a false finding if it is not documented.

A third error is the assumption that a signed form covers every service. A consent for video sessions may not cover a phone session or a different modality. The review should check the covered services field, not only the signature. If the field is missing, the reviewer cannot assume coverage. That limitation belongs in the report rather than in a private note.

## Review cadence

Run the review at quarter start and after any consent version change. A version change is a natural point to check whether the new form reached the clients it should cover. Keep the same session-level method so the comparison is meaningful. If the practice changes platforms, treat the first cycle after the change as a new baseline and label it clearly.

Assign the review to the compliance or intake lead and a backup. The reviewer should be able to export the session list and the consent audit trail without asking for special access each time. Document the access path and the matching rule. A review that depends on one administrator's login is fragile and hard to repeat.

Close the cycle with one change and a follow-up date. The change might be an earlier renewal reminder, a required version field, or a location confirmation at check-in. At the next cycle, check the same category and the same pre-session measure. If the change did not move the number, examine whether the reminder reached the client before replacing the design.
