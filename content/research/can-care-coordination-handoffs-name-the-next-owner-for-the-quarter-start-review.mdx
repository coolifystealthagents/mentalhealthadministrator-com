## Question and scope

This review asks whether care coordination handoffs name the next owner, the date a reply is due, and the question that remains open. The question is about the handoff record, not about the quality of the coordination. A well-intentioned message that names no person cannot be tracked, and a tracked message with no question cannot be closed. The review tests the record against those three elements.

The scope should name the coordination types included: school contacts, primary care, psychiatry, community services, and internal care team messages. Each type may have a different channel and a different expected response time. Mixing them without a stratum can hide a type that is systematically weaker. State the categories and the window before collecting entries.

Decide whether the review covers every message or only messages that represent a handoff. A routine update is not the same as a request for action. The population should be the messages that ask another person to do something or decide something. Include the follow-up messages that close the loop, because they are part of the same handoff.

## Population and unit of analysis

The population is every coordination handoff initiated inside the window for a client served by the practice. The unit is one handoff thread, from the first request to the documented response or closure. If a thread covers two distinct decisions, count two units and note the shared thread. Counting messages instead of threads overweights a long conversation and underweights a single clear request.

Exclude general announcements and messages that do not ask for an action. Include messages sent to an external partner, because those handoffs are often the most fragile. Include messages that were answered verbally and later documented, but mark the response time as approximate. The exclusion and inclusion rules should be applied before the sample is read.

Stratify by direction, partner type, and sender role. An outgoing message to a school may have a different response pattern from an internal message to a clinician. An administrative sender may use a different template from a clinical sender. Report the counts with each stratum and label small groups as provisional rather than treating them as a stable rate.

## Definitions and measures

Define a named owner as a specific individual responsible for the next action. A role such as the front desk is not a named owner unless the message also names the person currently in that role. A shared inbox is a channel, not an owner. If the practice uses a rotation, record the person on rotation and the backup at the time of the handoff.

Define the due date as the date by which the sender expects a response or decision. A message that says when you have a chance has no due date for this measure. A due date may be implied by a meeting date, but the review should only count it when the message states it. Implied dates are hard to audit and easy to dispute later.

The primary measure is the share of handoffs missing at least one of the three elements: owner, due date, or open question. Report each element separately as well, because a template that fixes one element may leave another weak. A secondary measure is the elapsed time from handoff to a documented response from the named owner. Report the oldest open handoff and the number with no response.

## Data sources and collection

Use the coordination log or the secured message system as the primary source. If the practice uses more than one channel, export each and combine them with a written matching rule. A single-channel export can miss the handoffs that moved to email or phone. Record the channel on each unit so the analysis can show whether the channel affects completeness.

Freeze the export at the review time and keep it with the method note. Do not rely on a live inbox that changes as messages arrive. If a thread is long, export the whole thread rather than the latest message, because the owner may have been named earlier. The reviewer should read enough of the thread to know whether the question was ever answered.

Use a pseudonymous client key and keep the crosswalk restricted. The review file should not include clinical detail from the coordination thread. Record the partner type, the sender role, whether the three elements are present, and the response time. A short coding sheet is easier to calibrate and safer to store than a full copy of the messages.

## Evidence standard

A handoff element counts as present only when it is visible in the message. A reviewer should not infer an owner from the recipient list or a due date from the meeting calendar. If the message refers to an earlier conversation that named the owner, the reviewer can count it only when the thread shows that conversation. The record should stand on its own for a later reader.

A response counts as documented when the thread contains a reply from the named owner or a note that records the owner's decision. A read receipt is not a response. A reply from someone else may be useful, but it does not satisfy the owner measure unless the owner was reassigned in the thread. The review should distinguish a response from an acknowledgment.

State what the review does not measure. It does not measure whether the coordination was clinically appropriate or whether the partner acted in the client's interest. It does not prove that a complete handoff produces a better outcome. The finding describes the structure of the record and the time to a documented reply. Those are process measures, and they should be reported as such.

## Analysis and reporting

Report the primary rate with the numerator, denominator, and window. Report the three elements separately so the reader can see whether the gap is ownership, timing, or clarity. Report the response time distribution and the share of handoffs with no documented response. A handoff open for weeks is a different problem from one that was answered late but answered.

Break the result down by partner type and channel. A high missing-owner rate on external handoffs may point to a template that was designed for internal use. A high missing-question rate may point to a habit of forwarding a message without stating the ask. The pattern should guide one template change rather than a broad instruction to communicate better.

Read the longest threads individually. A summary field can mark a handoff as answered while the actual decision remains open. The reviewer should note whether the thread closed with a decision, a referral, or a plan to revisit. A handoff that ends with we will follow up is not closed unless it names who will follow up and when.

## Limits and sources of error

The largest error is inconsistent channel use. If some coordinators use the log and others use personal email, the review will see only part of the work. Compare the log with a sample of actual coordination to estimate coverage. If the log is incomplete, the finding should say so and the practice should decide which channel is the system of record before measuring again.

A second error is a response that happened by phone and was never documented. The review can count only what the record shows, so a verbal response will appear as a delay. The practice should decide whether to treat an undocumented verbal response as a finding about documentation or as a gap in the measure. Either way, the report should not pretend the response time is exact.

A third error is a template that looks complete but is not used. A required field can be filled with a team name or a placeholder. The review should read the values rather than only checking for a non-empty field. If placeholders are common, the template needs a validation rule or a clearer instruction, not another reminder.

## Review cadence

Run the review at quarter start and after any change to the coordination template or channel. Keep the three-element definition stable so the comparison is meaningful. If the practice changes its messaging system, treat the first cycle after the change as a new baseline. A comparison across different channels should be labeled as descriptive.

Assign the review to the coordination lead and a backup. The reviewer should be able to export the threads and read them without special access requests each time. Document the export path and the coding rules. A review that depends on one person's inbox is not a sustainable control.

Close each cycle with one template change and a follow-up date. The change might be a required owner field, a due-date prompt, or a one-line question field. At the next cycle, check the same element and the same response measure. If the change did not move the number, inspect whether the template is being used as designed before adding another requirement.
