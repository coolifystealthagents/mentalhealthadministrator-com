An interpreter request can disappear when a visit is moved, copied, converted to telehealth, or assigned to another clinician. Treating it as a note attached to the old calendar slot creates that risk. A better design gives the request its own identifier and keeps it linked to the appointment through every scheduling event.

## Quick overview:

- Capture the person's stated language and communication request without having staff infer proficiency.
- Record who requested assistance, when, and through which channel.
- Link the request to both the person record and the current appointment identifier.
- Reconfirm vendor or internal interpreter arrangements after any time, location, modality, or duration change.
- Keep scheduling custody separate from decisions about legal obligations or appropriate accommodations.

## Give the request a durable record

A free-text calendar note is difficult to search and easy to drop. Use structured fields for requested language, spoken or signed modality, communication format, request source, date received, appointment identifier, service status, confirmation reference, and responsible coordinator. Include a source link so staff can consult the original wording when a field is disputed.

Do not use relatives, country of origin, an accent, or prior visit history to guess a language. "Not yet confirmed" is different from "not needed." If the person changes the request, retain the earlier value and the source of the correction instead of overwriting history.

The federal language access resource at [LEP.gov](https://www.lep.gov/) offers first-party materials about language access. A practice should obtain appropriate guidance for its duties and should not ask scheduling staff to make legal determinations.

## Define custody events

Custody should be checked whenever a scheduler performs one of these actions:

1. creates an appointment from a referral or waitlist entry;
2. changes date, start time, expected duration, site, or modality;
3. changes the assigned provider or service type;
4. cancels and recreates a slot rather than moving it;
5. merges duplicate person or appointment records; or
6. restores appointments after an outage.

The scheduler does not merely copy a note. The scheduler verifies that the active appointment points to the request record, changes the arrangement status to "reconfirmation required" when relevant details changed, and assigns the next task.

## Use statuses that describe observable facts

A compact status model prevents "interpreter arranged" from hiding uncertainty:

| Status | Evidence needed | Next owner |
| --- | --- | --- |
| request captured | source and requested language recorded | language access coordinator |
| request clarification pending | approved outreach attempt recorded | designated reviewer |
| service requested | vendor or internal request reference | coordinator |
| service confirmed | provider, mode, time, and confirmation ID | scheduler |
| reconfirmation required | changed appointment field identified | coordinator |
| exception under review | reason and authorized owner named | practice lead |

Avoid a generic "complete" status before the appointment occurs. A vendor confirmation might later be canceled, or a telehealth link may not support the planned service. The day-before or practice-selected check should compare the current slot details with the confirmation details.

## Work a rescheduling example

Suppose an in-person 50-minute appointment with a confirmed interpreter moves to a 30-minute telehealth slot on another day. The scheduler changes the appointment, preserves the prior confirmation, marks the request for reconfirmation, and sends only the approved operational details through the approved channel. The coordinator then records the new confirmation or routes an exception.

The scheduler should not decide that the shorter visit no longer needs an interpreter. Nor should staff tell the person that a family member is an acceptable substitute unless an authorized policy and reviewer support that communication. The process preserves the person's request while leaving legal, clinical, and accommodation decisions with the proper role.

## Reconcile calendars and service confirmations

Run a forward-looking report for appointments carrying a language access request. Compare appointment date, time zone, duration, site or video mode, cancellation state, and provider against the related service confirmation. Highlight mismatches rather than silently updating one system from the other.

Useful process measures include appointments with a request but no assigned owner, changed visits awaiting reconfirmation, confirmations lacking a matching active appointment, and post-visit disposition not recorded. Define each denominator and exclusion. These indicators reveal administrative gaps, not the quality of interpretation or care.

Common failures are copied appointments that omit custom fields, vendor emails stored only in one employee's mailbox, cancellations that do not reach the service provider, and duplicate requests submitted after a calendar move. Each needs a concrete repair: required transfer fields, shared approved records, cancellation tasks, and duplicate-linking rules.

## Frequently asked questions

### May staff choose a language based on a previous appointment?

No. Prior data can prompt verification, but the current record should reflect the person's stated request or another approved source. A conflict should be routed, not resolved by assumption.

### What if an interpreter vendor has not confirmed?

Keep the status pending, retain each request attempt, and escalate according to the practice's lead-time rule. Do not mark the arrangement complete merely because a request was sent.

### Does moving an appointment always require a new request?

Not necessarily. It always requires a custody check. The resulting action depends on what changed, the existing confirmation, and the practice's arrangement procedure.

## Keep language access attached to the active visit

The practical test is simple: can a reviewer start with tomorrow's schedule and identify every current request, arrangement state, and next owner without searching personal inboxes? Pair the record design with [accommodation request routing](/blog/route-accommodation-requests-authorized-review) and use [appointment roster governance](/blog/govern-group-appointment-roster-changes) where calendar changes involve shared services. Custody is successful when a scheduling change produces a visible follow-up, not an orphaned note.
