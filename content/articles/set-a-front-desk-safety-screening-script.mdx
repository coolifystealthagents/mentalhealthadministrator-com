## How to approach: Set a front-desk safety screening script

A safety screening script should be short, approved, and easy to use during a call. Start with the questions, the record, and the route. A script that invites the receptionist to assess risk crosses the boundary. Keep the original note beside the corrected version. A note that cannot be reconstructed later is not a control.

Keep the script visible at the front desk. The receptionist should not have to find the questions during a difficult call. Keep the boundary visible in the place where the work is assigned. A control that depends on memory is not yet a control. The review should end with one owner and one date. The team should test the script with a real call type.

## Use the approved questions

Write the questions exactly as the clinical lead approved them. Do not improvise or add a question during the call. A changed question can produce an answer that is hard to interpret. Write the deadline as a date and a local time. The authorization should be checked before the session. The practice should keep the clinical question with the clinical owner.

Record the version and the approval date. A later review may need to see what was asked. A short note with four fields is easier to use than a long narrative. Review the first few notes together before the process expands. The practice should keep the old form with the change note. The records release should name the authority and the scope.

## Record the answer and the route

Write the answer in the client's words. Do not summarize it into a risk level. Route the answer to the named clinician or the crisis path. Write the deadline as a date and a local time. The authorization should be checked before the session. The records release should name the authority and the scope.

Record the date, the time, and the person who received the concern. A concern without a route is not a control. Record the date and the source so the next reviewer can repeat the check. Review the first few notes together before the process expands. The practice should keep the old form with the change note. The authorization should be checked before the session.

## Test the script with the team

Read the script with the front desk and the clinical lead. Ask which question is unclear. Update the wording before the next shift. Keep the evidence with the record rather than in a separate log. The front desk should record the caller's relationship before sharing any detail. The practice should review the wrong-route calls monthly.

Record the test date and the change. A script that is never tested is only an intention. Ask whether a new reviewer could act on the record without a conversation. Record the date and the source so the next reviewer can repeat the check. The records release should name the authority and the scope. The practice should keep the old form with the change note.

## Review the script quarterly

Review the script with the clinical lead. A new policy or law may require a new question. Record the review date. Test the rule on one real call before applying it to the queue. The review should end with one owner and one date. The record should show the date and the channel of the contact.
